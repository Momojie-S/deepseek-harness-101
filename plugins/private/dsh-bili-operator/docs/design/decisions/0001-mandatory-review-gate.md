# ADR-0001: 合规审查门放在工具层强制前置，fail-close

状态: accepted（2026-11-13 起载体由四个专用写工具变为单一 `bili` 入口的识别表，原则不变，见 ADR-0005）

## 背景

四个内容发布工具（评论/回复/私信/动态）以账号身份对外发布文本，MomoYu 项目要自主运营，要求回复内容必须经过一次无上下文的大模型审查，防隐私泄露与违规。审查可以放在三层：运营会话提示词里"要求 agent 自己先审"、独立审查会话、工具层拦截。

## 备选

- **提示词约束**：让运营会话"发送前先自查"。零实现成本，但约束可被模型忽略，等于没有强制；且会话上下文会污染自查（自己说服自己）。
- **独立审查会话**：每条回复起一个无前提子会话。隔离彻底，但每条一次完整 agent 启动，成本高一个数量级，内容判定用不到工具与多步推理。
- **工具层拦截 + 一次性模型调用（ctx.llm hand-built one-shot）**：审查内嵌在发送路径上，绕不开；判官只收判据+草稿+原始内容，零会话残留。

## 决策

工具层强制前置：四个写工具在非 `dry_run` 时必须先过 `ReviewGate`，判定 `{verdict, reason}`；block 则工具直接返回拦截结果，CLI 调用根本不发生。审查用 `ctx.llm.stream` 一次性调用（无 Session 身份，不产生任何会话记录）；**fail-close**——审查调用失败/超时/输出无法解析一律拦截，绝不静默放行。每次判定（含拦截与放行）追加写入 `~/.dsh/bili-operator/audit.jsonl`。

绕过路径一并封堵：`bili_run` 直通工具只接受只读命令白名单（见 ADR-0002），运营会话按 workspace 收窄工具面。残余绕过面（用户在终端手动跑 CLI）不设防——那是人类操作。

## 后果

- 审查判据、审查模型、超时全部走配置（设置页热生效），默认模型兜底。
- 每次真实发送多一次小模型调用（几百 token），延迟秒级；`dry_run=true` 预览不过门，便于草稿迭代。
- 审计文件只追加不轮转，量级（条/天）远小于轮转需求；后续需要时再加。

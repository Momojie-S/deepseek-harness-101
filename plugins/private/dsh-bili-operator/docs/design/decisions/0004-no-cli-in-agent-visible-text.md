# ADR-0004: agent 可见文本不暴露 CLI 的存在

状态: accepted

## 背景

插件的 17 个工具底层是逐次调用 `bili` 命令行工具。初版工具描述里多处出现"CLI""命令行""子命令""请用户在终端执行"等表述，错误返回里也有"bili CLI 启动失败"。这些文本全部进入模型上下文——agent 一旦推断出工具背后有条可直连的命令行路径，就可能在自己有 shell 的会话里尝试绕过插件直跑（运营 workspace 里用户本人的交互会话没有执行守卫，只有运营会话有）。

## 备选

- **保持原样**：描述更准确、排障信息更具体；代价是把绕过路径的存在主动教给模型。
- **只清理工具描述，错误消息保留**：省事，但错误消息（"bili CLI 启动失败"）同样是模型可见文本，泄露量没有实质减少。
- **agent 可见文本全部去 CLI 化（描述、参数说明、错误消息、拒绝提示）**：模型视野里只剩"一组 bili 工具 + 一个只读查询直通"，无从推断直连路径。

## 决策

agent 可见文本一律不出现 CLI / 命令行 / 终端 / 子命令字样：

- 工具描述与参数说明：`bili_run` 表述为"B站只读查询直通：仅放行白名单内的只读查询"，参数示例保留 `["video","info","BV…"]` 形态（这是工具用法，不指向外部可执行物）。
- 工具返回与错误消息：超时写作"操作超过 X 秒未完成"，启动失败写作"B站服务暂不可用"，无输出写作"bili 服务无响应"。
- 拒绝提示只指向带审查门的专用工具，不再建议"让用户在终端执行"。

判定标准：凡是会进入模型请求或工具返回的字符串（工具描述、参数说明、`render` 输出、错误 message/hint、运营章程）都受此约束；代码注释、设置页文案（仅人类可见）不受限。2026-11-13 起约束面扩展：skill 正文与 references（`skills/bili-operator/`，改写自上游）同属 agent 可见文本，适配版已清除 CLI/命令行/终端/安装类字样，上游 attribution 保留在插件 README（人类层）。

## 后果

- 排障时模型收到的错误更笼统（"服务暂不可用"），具体原因要看插件日志与 `~/.dsh/bili-operator/audit.jsonl`——可接受，人类排障本就不该依赖模型转述。
- 措辞约束是纪律而非机制：新增工具或改文案时可能无意带回 CLI 字样，靠 review 与本 ADR 的判定标准把关。
- 防线纵深不变：运营会话 shell 是执行级拒绝（守卫），本 ADR 解决的是其余会话的"教唆"面；凭据隔离（规划中）补上最后一层。

## 5. 升级建议

- **不建议原样直升**：dsh-archive-retention 的 `installSection` 调用在 0.1.7 下必炸，且有阻断整个 DSH 启动的风险。**先改代码或先在该插件 patch 行加 `disabled: true`，再升级**
- **建议顺序**：
  1. 修/禁 dsh-archive-retention（§4 表内迁移路径）；同批顺手修 dsh-subagent-cleanup 的 v4 探测（小改动）
  2. 升级：`npm i -g @deepseek-ai/dsh@0.1.7-rc.2`（内部包精确 pin，无 vendor 漂移空间）
  3. **preset 移植（工作量大头）**：`momojie-common` 所依赖的 `~/.dsh/.agent-presets/` 目录机制已删除——需把该 preset 重写为 profile patch 行（`agent-preset-registry` 设 default + `agent-preset` 条目携带 ptc 插件清单），`thresholdRatio: 0.5` 改写到 `compaction-basic` 的 config，both 模式按新 config 形态重申；`docs/official-usage/agent-presets.md` 与开发指南相关章节升级后需同步改写（不在本次范围）
  4. 检查 `settings.yaml.imported`：若生成，说明旧设置文档被导入+改名，`archive-retention` 等 section 按需手工搬到对应条目的 patch config
- **升级后优先验证**：① 启动是否成功、stderr 有无 "disabling profile plugin"（peer 校验/兼容拒绝）；② pwsh 工具跑一条带 workspace `.env` 的命令（workspace-env 的 private 包装面）；③ `.dsh/mcp.servers.yml` server 注册日志（workspace-mcp 三事件面）；④ subagent 派生 + `send_message` + settle 通知一轮（schedspawn/idle-delivery）；⑤ `subagent_cleanup` dryRun 一轮（v4 目录下能列出局且不误判活跃会话）；⑥ 设置页能开、插件卡片正常（设置重构后 UI 面全换）；⑦ 打开一个旧会话确认 v4 自动迁移无报错
- **机械项（择期）**：5 个带 peer 的插件把 `@deepseek-ai/dsh-*` 范围 bump 到 `^0.1.7-rc.2`（消除未来硬校验风险）；清理 schedspawn prompt 的 `subagent_model` 文案
- **本次不升亦可**：0.1.5-rc.1 继续运行无安全公告压力；但 0.1.5 线已止于 rc.3，后续修复都在 0.1.7 线，拖延会拉大 preset/设置两套机制的迁移成本

## 3. 用户视角差异（最实用）

1. **MCP 工具结果里的图片现在能进模型上下文**（PR #2252 rich-content-bridge，issue #1463）：`dsh-mcp-client` 收到含 image block 的 MCP 结果时，校验 MIME（png/jpeg/webp/gif）与规范 base64，经 attachments 服务持久化后把图片作为 image block 投影给模型；模型无视觉能力或校验失败时降级为 `[image unavailable: ...]` 文本占位，原始数据仍保留给程序化调用者。此前图片一律 `[image: ..., content discarded]`。**对本机 GLM 文本主力模型：无视觉 → 仍显示占位文本，但语义更明确；VLM 路由（qwen3.7-plus 等）经 MCP 拿图成为可能。**
2. **run_code 的子工具图片结果自动附带**：run_code 执行中成功的含图工具结果会在 run 结束后 defer 进上下文（`dsh-tools` code-mode），SDK 说明文案同步更新（"Image-bearing subtool results are attached after the run"）。
3. **read_image 行为变化**：`dsh-tool-fs` 删除了"父代理 deferContext 图片消息"的逻辑——read_image 现在统一走 attachments 投影通道，子代理（run_code 等场景）读图的附带路径收敛到 dsh-tools 的新机制。
4. **max-tokens 截断的 replay 一致性修复**（PR #2596）：`dsh-llm` BlockAssembler 把 keep/drop 决策与 replayState 收敛到同一处，截断丢弃 tool-call 块时 replay 元数据同步裁剪，新增 `ReplayEnvelope` 类型（`replayState` 从 `unknown` 收紧）。DeepSeek 路由下截断续跑不再出现 blocks 与 replay 不一致。
5. **preset 字段：`enableRunInBackground: false` → `backgroundMode: one-shot`**（PR #2374）：三个内置 preset（code/cordis/standard）中 `tool-subagent-codex` / `tool-subagent-claude_code` 两个 disabled 行改用新字段；注释明确"生产 dsh 不安装这两个可选 provider，Profile 需自行安装 `@deepseek-ai/dsh-subagent-codex` / `dsh-subagent-claude-code` 并挂载"。**本仓 `ptc-early-compact` 用户 preset 基于 rc.6 code preset——若其中复制过这两个 disabled 行或用到 `enableRunInBackground` 字段，升级后需对照重套（本仓 preset 目前未含 subagent 行，见 §4）。**
6. **"Code mode" 更名 "PTC mode"**（PR #2559）：client UI 中 code preset 显示名改为 PTC mode（`dsh-client-ui-agent-preset` client.js）。
7. **bash 持久 shell 修复**（PR #2586 等）：`tool-bash-persistent` 放弃 `__DSH_PERSISTENT_BASH_PROMPT__` PS1 探测方案，改用 `waitReason === "stdin_read"` 判定命令结束；`terminal-bash` 的 PROMPT_COMMAND 强制重设 PS1。Windows 本机用 pwsh 工具为主，影响有限，但 bash persistent 会话的输出截取更可靠。
8. **host-apiproxy 设置面收敛**（PR #2404 plugin-owned-settings-surface）：删除 `WEB_SETTINGS_NAMESPACES` / `PRODUCT_SETTINGS_NAMESPACES` 白名单硬编码（改为插件自注册暴露）；web 发多图 prompt 从逐张 `saveImage`+预校验改为批量 `saveImages`。
9. 破坏性变更：**未发现用户可见的破坏性变更**——主包入口、CLI、工具名均未变。

## 5. 升级建议

- **可以升**：本仓 5 个插件无一被 rc.7 破坏，全部接口（含 private `spawnSpec`）在 rc.7 产物中逐一验证仍在。
- **先后顺序**：① 升级 DSH（重装全局包）→ ② 重启 web 服务 → ③ 冒烟：web 开会话确认各 bundle 插件加载、pwsh 调用带 workspace `.env`（workspace-env 生效）、`.dsh/mcp.servers.yml` server 注册（workspace-mcp 日志）、文件面板与 right-dock UI 正常 → ④ 顺手 cherry-pick subagent-model 的 AggregateError 修复 → ⑤ 对照 rc.7 code preset 核对 `ptc-early-compact` 漂移（本版 preset 变化点：subagent disabled 行的 `backgroundMode` 字段与注释；按 `docs/usage/agent-presets.md` 重套流程）。
- **升级后优先验证**：workspace-mcp 的 MCP 连接与工具注册（官方 mcp-client 大改，虽不影响本插件自移植版，但 web profile 里若还挂了全局 `@deepseek-ai/dsh-mcp-client` 插件实例，其 rc.7 版行为变化——图片准入、对 `attachments`/`llm` 服务的 `ctx.get` 依赖——会在无 attachments 服务挂载时把图片降级为占位文本，属预期降级非故障）。

## 6. 方法与局限

- **硬证据**（tarball 对比）：§2 的包级变化清单、§3 的全部 diff 细节、§4 的接口存在性验证，均来自 `$env:TEMP\dsh-verdiff` 下两版 tarball 解包逐文件 MD5 对比与 `git diff --no-index`。
- **源码仓证据**：first-parent 区间 `15148dbd9a..bb4ca698d6`（23 个 merge）与 PR 标题相互印证（#2252 rich-content-bridge ↔ mcp-client 图片；#2374 ↔ backgroundMode；#2559 ↔ PTC mode；#2596 ↔ max-tokens replay；#2404 ↔ settings surface）。
- **局限**：
  - 本地源码仓工作区是旧 checkout（版本号 rc.5），grep 工作区找不到 rc.7 代码属正常，已改用 origin/master 对象对照；
  - release 分支合流使全量 commit 区间（12,396）失真，未逐 commit 归属功能，PR 级对应关系由 tarball diff + merge 标题交叉确认；
  - client 侧（client-ui-cordis 等）是打包产物，只能做模式筛选级验证（slots 相关行无变化），未做源码级确认；
  - 未实际安装 rc.7 运行验证（任务边界：只调查不升级），§4 结论基于产物静态对比，升级后的运行时行为以 §5 冒烟清单为准。
- **未确认项**：`@deepseek-ai/dsh-agent-presets` 包（host-apiproxy 的 import 来源）不在主包依赖清单内未单独对比，其 rc.7 行为由 host-apiproxy diff 间接推断（`SETTINGS_NAMESPACE` import 移除）；未发现影响本仓插件的迹象。

## 1. 版本概览

**这是一次"公开发布"版本，不是功能版本。** 全部实质性变更集中在包发布元数据：

- **入口包 `@deepseek-ai/dsh`**：tarball 内 20 个文件中仅 `package.json` 有差异（70 行），内容为：
  - `version`: 0.1.0-rc.3 → 0.1.0-rc.6
  - `publishConfig.access`: `restricted` → **`public`**
  - 全部 59 个 `@deepseek-ai/dsh-*` 运行时/dev 依赖从 `^0.1.0-rc.3` bump 到 `^0.1.0-rc.6`（`@deepseek-ai/cordis ^4.0.1` 与 4 个 `cordis-plugin-*` 版本范围不变，不属于家族 bump）
  - `lib/*.js`（bin.js、profile-boot、plugin、dump-config）与 `config/agent-presets/**`（code/cordis/minimal/standard 四套 preset + cordis 技能）**逐字节相同**
- **65 个内部 `@deepseek-ai/dsh-*` 包**（npm pack rc.3/rc.6 各自解包、逐文件 MD5 对比）：**全部仅 `package.json` 变化**（版本号 + publishConfig public + 内部依赖范围 bump），`lib/` 代码逐字节相同
- **唯二有 lib 差异的包**：`dsh-client-ui-agent-preset` 与 `dsh-client-ui-cordis` 的 `lib/client.js`——差异**全部是 CSS module 对象的键序重排**（类名与哈希值逐项相同，如 `SVAs4q_label`、`rtSEdW_*`、`Nqubda_*`，仅键的排列顺序不同），为构建产物非确定性，无任何语义变化
- **版本跳号说明**：rc.4、rc.5 从未发布到 npm（`npm view` versions 无此二者）；rc.5 出现在 release PR 标题中（准备发布的版本号），最终以 rc.6 落地

涉及包规模：入口包 1 + 内部包 65（dependencies 59 个 dsh-* + devDependencies 12 个 dsh-* 去重），全部为联动 bump；无新增/删除的内部依赖（对照 rc.3/rc.6 依赖清单，仅顺序与版本号变化）。

## 3. 逐插件影响评估

先说结论：**三个插件全部"无需改动"**。依据是：插件触碰的每一个 DSH 接面，其在 rc.6 的实现产物与 rc.3 逐字节相同（tarball MD5 对比），且在源码仓快照（= rc.6 发布状态）中逐一验证了存在性与签名。

| 插件 | 触碰的接面 | 新版（rc.6）变化 | 结论 | 预估改动量 |
|---|---|---|---|---|
| dsh-workspace-env | `inject ['shell']`；包装 `ctx.shell.spawnSpec`（pwsh-local 的 **private** 方法） | 无（dsh-pwsh-local lib 逐字节相同） | 无需改动 | 0 |
| dsh-workspace-mcp | `inject ['tools']`；`ctx.on('agent/created'/'agent/pre-step'/'agent/disposed', {global:true})`；`agentCtx.tools.register({output.render})`；`agent.session.header.cwd`；自备 `@modelcontextprotocol/sdk` | 无（事件、注册契约、会话头字段均在源码快照验证存在；MCP SDK 是插件自有依赖，与 DSH 版本无关） | 无需改动 | 0 |
| dsh-subagent-model | fork 自 `dsh-tool-subagent`；`defineTool`(dsh-tools)、`assertSubagentMaxDepth`/`settleRun`(dsh-subagent)、`inject ['tools','subagents','systemPrompt']`、`subagent/provider-added|removed` 事件、`ctx.subagents.getProvider/start/startContinuable`、`ctx.get('llm'/'jobs')`、`ctx.systemPrompt.section`、`ctx.tools.get` | 无（上游 tool-subagent lib 逐字节相同 → fork 零漂移；全部导出与服务方法在 rc.6 tarball 与源码快照中验证存在） | 无需改动 | 0 |

### 3.1 dsh-workspace-env

- **包装点**：`plugins/dsh-workspace-env/src/index.ts` L94-107 绑定并替换 `shell.spawnSpec`。该方法定义于 `packages/shell/pwsh-local/src/index.ts` L222（`private spawnSpec(spec, stdoutMaxBytes, signal, argv): SubprocessSpawnSpec`，返回 `{argv, cwd, stdio, graceMs, signal, env: {...ENV_OVERRIDES, ...spec.env, ...spec.dshEnv}}`，env 组装顺序 L240）
- **rc.6 验证**：`dsh-pwsh-local` rc.3 vs rc.6 tarball 除 `package.json` 外逐字节相同 → 方法、签名、env 合并语义全部不变。插件的 `(spec, ...rest)` 包装与 `result.env` 覆写继续成立
- **风险注记**：该方法仍是 `private` 非契约接面，本次无变化，但**每次升级都要重新确认**（本次报告已确认 rc.6 安全）
- 该插件未声明任何 peerDependencies（源码用 `ctx: any`），无版本约束问题

### 3.2 dsh-workspace-mcp

- **事件**：`agent/created` / `agent/disposed` / `agent/pre-step` 签名见 `packages/core/agent/src/runtime-types.ts` L159/L168/L231（payload `{agent}`、`{agent, messages, turn, step, signal}` + next），源码快照（=rc.6 状态）与 rc.3 行为一致

- **会话头**：`agent.session.header.cwd` 访问路径无变化
- **自有依赖**：`@modelcontextprotocol/sdk ^1.12.0`、`chokidar ^5`、`js-yaml ^4` 均由插件自带，与 DSH 升级解耦
- **peerDependencies 已声明 `^0.1.0-rc.6`**（dsh-invariants/dsh-session/dsh-tools/cordis/schemastery），与升级后版本匹配

## 4. 升级建议

- **升不升：升，随时可升。** 代码层 rc.6 ≡ rc.3，唯一差异是 npm 可见性；且本机安装**已经是 rc.6**（见头部勘误），插件 junction 已实际解析到 rc.6 内部包上运行
- **顺序**：无需顺序安排。若在多机部署：直接 `npm i -g @deepseek-ai/dsh@0.1.0-rc.6`（rc.6 起无需 registry 授权），重启 DSH 进程即可；插件仓不做任何改动
- **升级后优先验证**（低成本冒烟，非必须——代码零变化使回归风险≈0）：
  1. `dsh web --dump-config 2>&1 | Select-String 'workspace-mcp|workspace-env|subagent'`——三个插件行正常出现
  2. 任一 workspace 放 `.dsh/mcp.servers.yml`，开新会话确认首条消息可见 `mcp__*` 工具（workspace-mcp 的 created 时序路径）
  3. workspace `.env` 注入一次（workspace-env 的 spawnSpec 包装路径）
  4. `subagent_model` 工具调用一次含 `model` 参数（subagent-model 的 fork 路径 + `llm` 校验路径）
- **无需改任何文档/配置**：preset、profile patch 格式、`.dsh/mcp.servers.yml` 格式均无变化

## 5. 方法与局限

**确凿来源的结论**（tarball 字节级对比，证据可再生）：

- 入口包仅 `package.json` 变化：`npm pack @deepseek-ai/dsh@0.1.0-rc.3 @0.1.0-rc.6` 解包后 `git diff --no-index`，1 file changed（临时目录对比，已清理）

- 两个 client 包仅 CSS 键序重排：diff 逐行核对，键值对（类名→哈希）完全一致仅顺序不同

**局限与未确认**：

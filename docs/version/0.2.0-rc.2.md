### 细节与注意点

- **peer 硬校验 0.2.0 起咬人（本次最重要发现，实测）**：上版已证校验逻辑为 `semver.satisfies(runtimeVersion, range, { includePrerelease: true })`（`boot/app-boot/src/plugin-compatibility.ts:77`），不满足的条目启动时被置 `disabled: true` 并在 stderr 报 "disabling profile plugin"（`compatibility-preflight.ts` 含该文案）。上版实测 `satisfies('0.1.7-rc.2','^0.1.1-rc.2') === true` 并预言 "0.2.x 时会咬人"——**本次实测应验**：用 dsh 安装树内嵌 semver 跑 `satisfies('0.2.0-rc.2', '^0.1.1-rc.2', {includePrerelease:true})` = **false**。机制：caret 范围上界脱糖为 `<0.2.0-0`，排除 0.2.0 的一切预发布版（`0.2.0-rc.2 > 0.2.0-0`），与 includePrerelease 无关；0.1.x 时代版本元组落在界内所以通过。校验只看名字为 `@deepseek-ai/dsh` / `@deepseek-ai/dsh-*` 的 peer（vendor peer 如 cordis/schemastery 被过滤跳过），本仓 5 个带 `dsh-*` peer 的插件（`^0.1.1-rc.2`）**全部命中**
- **两条出路**：① bump peer（推荐根治：每插件 package.json 的 `peerDependencies` 改 `>=0.1.1-rc.2` 或 `^0.2.0-rc.2`，合计 ~15-19 行，另官方还认 `workspace:^`/`workspace:~`/`workspace:*` 三种写法并自动视为满足，见 `plugin-compatibility.ts` 的 requirement 替换逻辑）；② 临时豁免：profile 目录下 `compatibility.json`（`profile-compatibility.ts:15` `PROFILE_COMPATIBILITY_FILENAME`），键为**精确** `插件名@插件版本`、值为**精确** DSH 版本数组（`isExactPluginVersion` 只收精确 semver，范围/前缀直接抛错）——例如 `"@momojie-s/dsh-schedspawn@<当前版本>": ["0.2.0-rc.2"]`
- **同 id 内置 entry 检查（AGENTS.md 教训项，跨版本必做）**：`docs/config-catalog.md` 与 `docs/tool-catalog.md` 对 `workspace-env`/`workspace-mcp`/`schedspawn`/`subagent-cleanup`/`idle-delivery`/`archive-retention` 及注册工具名 `schedspawn`/`subagent_cleanup`/`subagent_cleanup_global` grep 全部 **0 命中**。官方新增 user-questions 工具族（ask_user_question 面板）、Automation tasks（schedule_*）与上述无冲突。**无撞名风险**
- **本机 schedule patch 行的前途**：`cordis.patch.yml:48-50` 的 `- insert: id: schedule, name: '@deepseek-ai/dsh-schedule'` 在 0.2.0 下先会变成 "entry not found" 警告；官方指引说启用 bundle 后既有 id 定向行"字段覆盖重新生效、纯 disabled:false 行可删"。本行是**无额外字段的 insert 形态**，与 bundle 插回的同 id 行是否构成 duplicate-entry 冲突**未确认**（见 §6）——升级时建议走 Plugins 页开关让官方代码写 bundles，再观察启动日志决定该 insert 行去留
- **preset 迁移配方官方化**：新版在 `dsh-agent-preset` 包里带了官方 skill：`packages/preset/agent-preset/skills/editing-cordis-compositions/SKILL.md:70` 明说旧 `~/.dsh/.agent-presets/<id>/` 目录"Nothing reads that directory any more"并给出逐字段迁移配方（`preset.yml` 的 name/description/order + `agent.cordis.yml` 的插件清单 → bundle 声明行）。本机该目录仍在（`Test-Path` 实证 True），`momojie-common` 迁移照此配方执行即可——0.1.7 报告的迁移判断不变，且现在有官方一步步指引
- **遗留文案**：schedspawn prompt 中 `subagent_model` 引用原样还在（本仓自身问题，与版本无关，连续三版报告提及）

## 5. 升级建议

- **可以升，但裸升必残**：不处理 peer，5 个插件启动即被自动禁用（功能静默消失，不报错崩进程，更容易漏察觉）；不处理 archive-retention，整个 DSH 可能起不来。**先改这两处再升**
- **建议顺序**：
  1. **peer 范围 bump**（5 个插件 package.json，根治项，~15-19 行）；时间紧可先写 `compatibility.json` 豁免顶住
  2. **修/禁 dsh-archive-retention**（迁移路径见 §4 表 + 0.1.7 报告细节，结论不变）；同批顺修 dsh-subagent-cleanup 的 v4 探测（小改动）
  3. 升级 `npm i -g @deepseek-ai/dsh@0.2.0-rc.2`（内部精确 pin，无 vendor 漂移空间）
  4. **preset 移植**（若尚未做）：按官方 skill 配方把 `momojie-common` 重写为 bundle 声明行，`thresholdRatio: 0.5` 写进 `compaction-basic` config（`docs/config-catalog.md:694` 仍在）；完成后删旧目录
  5. **Automation tasks 启用**：Plugins 页打开官方 "Automation tasks" 开关（自动往 profile `package.json` 的 `dsh.profile.bundles` 追加 `@deepseek-ai/dsh-experimental-schedule-bundle`），然后按 §4 处理旧 schedule insert 行；不启用则定时提醒功能就此停用
  6. 检查 `settings.yaml.imported` 是否生成（0.1.7 的一次性导入机制，archive-retention 旧设置 section 需手工搬运）
- **升级后优先验证**：① 启动 stderr 无 "disabling profile plugin"、无 "patch: entry … not found"；② pwsh 工具跑一条带 workspace `.env` 的命令（private 包装面）；③ `.dsh/mcp.servers.yml` server 注册日志；④ subagent 派生 + `send_message` + settle 通知一轮；⑤ `subagent_cleanup` dryRun（v4 目录口径）；⑥ 设置页 + 插件页正常；⑦ 打开旧会话确认 v4 迁移无碍；⑧ **Windows 沙箱跑一条命令**（#5432 ACL 修复与本机直接相关）；⑨ Automation tasks 页出现且已存提醒可投递
- **机械项（择期）**：各插件 README「环境要求」验证基准版本号跟进；schedspawn prompt 的 `subagent_model` 文案清理
- **本次不升亦可**：0.1.5-rc.1 无安全公告压力；但 0.1.5/0.1.7 线均已止，后续修复都在 0.2.0 线，拖延会拉大 preset/设置/schedule 三套机制的迁移成本

## 6. 方法与局限

- **硬证据（tarball，`%TEMP%\dsh-verdiff-0200`）**：三版主包 `npm pack` + 解包，package.json 依赖逐名比对（72→81→82、+1 名单、pin/vendor 范围逐项）；lib 结构计数（5→7 js、+8 d.ts）
- **硬证据（git 区间）**：全口径与增量两段的规模数字与 merges 计数；`docs/` 69 处变更清单（13 处增删全部列出，含两份 upgrade guide 与一份 persistence change 原文通读）；§3 各项归因到 merge sha；§4 全部接面 `文件:行号` 在 `639ed01539` 正向 grep/show 验证（未 checkout）
- **硬证据（本机实测）**：semver 判定用 `node_modules/@deepseek-ai/dsh/node_modules/semver` 实跑（含 0.2.0-rc.2 对五种 peer 范围）；6 个插件 package.json 的 peer 清单、三个插件源码关键行（installSection :306、stillQuiescent :187/193、spawnSpec patch :94-97）直读；本机 web profile patch 与 package.json bundles 只读核对
- **推断项（依据充分但非运行实证）**：archive-retention 启动失败仍是"调用不存在方法抛 TypeError + 单插件失败阻断启动"的推演（与上版一致，未实装复现）；"5 个插件被自动 disabled" 基于校验源码 + 实测 satisfies 结果推演，未起 0.2.0 进程复现 disabled 行为与 stderr 文案
- **未确认项及原因**：

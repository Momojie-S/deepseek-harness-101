### 细节与注意点

- **升级阻断排序（本节最重要结论）**：rc.1 下本仓插件只有一个**启动阻断**（archive-retention 的 `installSettingsSection` 导入）和一个**运行时报错**（subagent-steer 的 `followup` 调用）。前者必须先修先禁，后者建议同批处理。
- **subagent-model 的"废弃"与 steer 的"废弃"性质不同**：前者接口全在、只是被原生功能替代（不升不坏，可与原生共存——插件工具名 `subagent_model` 与原生 spawn 工具并存，但原生白名单默认关、插件默认开，语义有差，长期应二选一）；后者是接口物理消失，升级即断。
- **`subagent/provider-added/-removed` 事件**：rc.1 的 `SubagentRuntime` 改为 `extends TypertRemoteService`（typert 校验层），但两个事件的 emit 点与载荷形状未变（`subagent/src/index.ts:147/519`），subagent-model 的 mount 逻辑不受影响。
- **`ContinuableStart` 返回 `childId`**：schedspawn/subagent-model 读的 `started.childId` 字段在 rc.1 `ContinuableStart` 接口保留（`continuation.ts` "The durable child session id, stable across activations"），spec 侧可选 `childId` 也 rc.2 已有，本次无形状变化。
- **peer 版本范围（机械跟进项，非阻塞）**：各插件 peerDependencies 仍钉在 `^0.1.1-rc.2`/`^0.1.0-rc.6` 系，按 node-semver 预发布规则匹配不到 `0.1.2-rc.1`；本机 junction 解析不受影响，`dsh plugin add` 路径会有告警。惯例做法：升级后把这批范围机械 bump 到 `^0.1.2-rc.1`。
- **cordis-plugin-timer 1.1.3→1.1.4**：三个用 `ctx.interval/ctx.timeout` 的插件的 peer 范围 `^1.1.3` 按常规 semver 覆盖 1.1.4，无需动作。

## 5. 升级建议

- **可以升，但不是裸升**：10 个插件里 8 个零改动，1 个机械小改（archive-retention），1 个建议废弃（subagent-steer）；另有 1 个建议顺势废弃（subagent-model，可延后）。
- **先后顺序**：
  1. **升级 DSH 之前**：先在 web profile 的 `cordis.patch.yml` 给 `dsh-archive-retention` 与 `dsh-subagent-steer` 两行加 `disabled: true`（灭火开关，防 bundle 阻断）；或直接先落 archive-retention 的 `installSection` 改造（~10 行）再升
  2. 升级 DSH 全局包（新依赖 acp-app/sdk-app/sdk-minimal/hooks-*/webhook-* 随主包装入）
  3. 重启 web 服务，确认 8 个（或 9 个，若 steer 已先禁）bundle 加载无错
  4. **升级后优先验证**：① archive-retention 改造后设置页卡片读写（改一个保留天数看 settings store 落值 + 30 秒 ticker 日志）；② 一次 pwsh 调用带 workspace `.env`（workspace-env 的 private 包装面）；③ `.dsh/mcp.servers.yml` server 注册日志；④ subagent 派生一次（原生 spawn 工具）+ `send_message` steer 一次（替代 steer 插件的路径）；⑤ right-dock / workspace-files 浏览器过一遍 UI（gate ④ 冒烟，DOM 锚点级验证本次没做）
  5. **preset 动作（本机特有）**：内置 `code` preset 已改名 `ptc`，用户副本 `ptc-early-compact` 若 `base` 钉的是 `code` 需改成 `ptc`（否则 base 解析失败；重套流程见 `docs/official-usage/agent-presets.md` 踩坑节）；顺带核对 ptc preset 新增的"workflow 工具默认移除"是否要跟
  6. （机械项）各插件 peerDependencies bump 到 `^0.1.2-rc.1`，重跑单测 + 原子构建
  7. （择期）subagent-model 废弃迁移：开 `subagent-model-selection` 设置白名单 → 验证 `list_subagent_models` → 下线插件
- **数据安全预期**：会话数据升级风险低——投影缓存有跨版本读兼容（#3438），投影有迁移框架（#2742），JSONL-only 改造默认压缩仍 zstd、产物路径布局未变；但会话文件从此可能出现 `.jsonl`/`.jsonl.zstd` 双格式并存的迁移态，subagent-cleanup / archive-retention 的 mtime 判据以默认后缀为准，升级后头几轮清扫结果值得瞄一眼。

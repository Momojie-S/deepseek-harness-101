## 1. 版本概览

- **变更区间**：npm 时间线 2026-10-17 → 2026-10-29，内含 rc.3、rc.4 两次发布。GitHub 侧 tag `dsh-v0.2.1-rc.2` → `dsh-v0.2.1-rc.4` 的 compare 报 **15 个 commit / ≥300 文件**（API 300 封顶截断）；rc.4 → rc.5 无源码锚点。
- **CLI 主包本体**（tarball 逐文件 SHA256 对比）：20 个文件中 **19 个逐字节相同**，唯一差异是 `package.json`——全部 `@deepseek-ai/dsh-*` 内部依赖统一 bump `0.2.1-rc.2` → `0.2.1-rc.5`，无新增/删除依赖。主包是元包，真实变更全在内部包。
- **内部包全景扫描**（registry tarball 下载 + 逐文件哈希，共 4 批）：
  - 主包直接依赖 83 个：**76 个纯版本号 bump**（自身版本 + 内部依赖版本串，lib 逐字节相同），**7 个有真实内容变化**；
  - `dsh-web-app` 依赖 133 个（承载全部 Web UI 包）：**114 个纯版本号 bump**，约 17 个有真实内容变化，另有 `dsh-client-ui-entry-customization` 为**新增包**（首发 0.2.1-rc.3，npm time 实测）；
  - 插件依赖的 host 侧包 21 个（`dsh-session`/`dsh-workspace`/`dsh-agent`/`dsh-subagent`/`dsh-tools`/`dsh-shell-env`/`dsh-llm`/`dsh-system-prompt` 等）：**全部纯版本号 bump，lib 逐字节相同**（`dsh-invariants` 自 0.2.0-rc.2 后停止发包，两版解析到同一 tarball，等效无变化）。
- **ranged 外围依赖解析不变**：`cordis ~4.0.5`、`schemastery ~3.18.5`、`cordis-plugin-{loader,include,timer}` 的最新稳定版均发布于 2026-10-16（rc.2 之前）；10-27 发布的 4.0.6-alpha.1 等是 prerelease，`~` 范围不会命中（npm versions/time 实测）→ **rc.2 与 rc.5 的安装解析结果一致**。
- **规模感觉**：这是一个「小步 rc」区间——产品代码变化集中在导航自定义、analytics、DeepSeek /models 跟随三条 feature 线和一批 UI/ACP 修复；**host 侧核心服务面（session/agent/subagent/tools/workspace/shell）零内容变化**。

## 2. 用户视角差异

### 新功能

- **导航条目自定义（More 菜单 pin）**：左侧栏面板、会话 View 标签页、右侧栏引导卡三个区域的「More」菜单支持固定/取消固定插件入口，菜单项带图标（#6247、#6883、#7342）。官方文档 `docs/subsystems/slots.md` 新增段落：三个 root-scoped slot 列表 `sidebar.panellist.actions`、`conversation.session.header.views.actions`、`sidebar.right.tab.guide.actions`，由新包 `ui-entry-customization` 注册出厂行。web 默认 patch 随之多一个内置条目 `entry-customization`。
- **预设选择 analytics**：agent-preset UI 接入 product-analytics，新增固定预设类目 `creator/ptc/minimal/standard`（`AnalyticsPreset`），座位控制器返回结构化 `AgentPresetApplyOutcome`（applied/staged/unchanged/refused）。
- **DeepSeek 官方 /models 列表跟随**：内置 DeepSeek API-key 路由按官方 /models 列表出模型，约 10 分钟后台刷新，失败回退内置表；模型选择器可显示列表角标（#6944、#7027；`docs/user/guide/providers.md` 已成文）。

### 行为变化

- **New Session 回归空白会话复用**：rc.2 起 New Session 每次新建全新会话（rc.2 的行为回归），本区间修复——重新复用 workspace 里第一个未启动、未归档的空白会话；指定 preset 的请求会**跳过列出其他 preset 的空白会话**（Creator 类入口不再抢占别的 preset 的草稿）。官方升级指南 `docs/upgrade-guide/v0.2.1-rc.2/new-session-blank-reuse/guide.md`。对预设工作流（本机 `momojie-common`）是日常可感知的变化：改 preset 定义后需让 Agent 重新组合（重启宿主或新组合的会话）才生效。
- **MCP resources 探测静默化**：MCP server 未声明 resources 能力时，resources 列表返回空结果而不是报错（对 ACP stdout 与日志更安静）。本机 chrome-devtools 等 MCP 走 `dsh-mcp-client`，行为是兼容性放宽，无破坏。

### 修复（GitHub commit 记录，包级实证以 §1 清单为准）

- View 标签页溢出才显示 tooltip、More 视图 tooltip 固定（`c38265a00e`/`72624bae95`/`199ffe37ba`）。
- ACP account catalog 诊断不再写 stdout（`41736cdec5`、`940aafcadb`）。
- 会话回合结束/steer 时的 transcript 稳定性、取消 Inbox 行时回收排队 echo（`ae07093132`、`a1659120a3`，落在 api-session-controller / client 侧）。

### 配置与 preset

- `dsh-web-app` 默认 `cordis.patch.yml` 新增 `entry-customization` 行（tarball diff 实证）——升级后 web profile 重建时默认装载该内置插件；已有 profile 不受影响。
- 内置 skill `cordis-composition-reference` 的 packages 参考表新增 entry-customization 条目（`dsh-agent-preset` tarball diff 实证）——升级后该 skill 注入内容多一行，无破坏。
- **无 preset 格式/schema 变化**：`dsh-agent-preset`、`dsh-agent-preset-registry`、`cordis-plugin-loader`、`schemastery` 的 lib 均 rc.2 == rc.5（哈希实证）。

### 细节与证据

1. **最脆弱点平安**：`dsh-workspace-env` 包装的 `ctx.shell.spawnSpec` 是 private 非契约方法（历史上最先断的位置）。本次 `dsh-pwsh-local`（shell 服务载体）tarball 内容 rc.2==rc.5，且在 rc.5 解包产物中 grep 到 `spawnSpec` 定义——包装语义无变化。
2. **同 id 冲突排查**（0.1.5 workspace-files 教训）：收集 rc.5 全部内置 patch 的条目 id（约 340 个，web-app/base/sdk-minimal/experimental 包全量提取），与本仓插件 id（`workspace-env`、`dsh-workspace-mcp`、`dsh-schedspawn`、`dsh-subagent-cleanup`、`dsh-subagent-idle-delivery`、`dsh-archive-retention`、`dsh-bili-operator`、`dsh-wechat-pad`、`dsh-zcode-coding-plan`）逐一比对——**零冲突**。rc.5 新增的内置 id 仅 `entry-customization`、`product-analytics` 等，均不同名。
3. **scheduler/spawn 链路无恙**：schedspawn 在 rc.2 就已完成 `startContinuable → startActivation + delivery:'parent'` 迁移（见 0.2.1-rc.2 报告 §3）；rc.5 的 `dsh-subagent` 内容一致，该适配继续有效。
4. **三方插件 peer 面**：dsh-zcode-coding-plan 声明 `dsh-tools@*`，rc.5 的 dsh-tools 仍与 rc.2 逐字节相同，无需动作。

## 4. 升级建议

- **结论：可升级，风险低。** 本区间没有任何 host 侧服务面/工具面/事件面变化（21 个插件依赖包内容零变化），9 个插件全部无需改动。
- **升级后优先验证**（按 §3 对应探针）：
  1. workspace-env：任一会话跑一条读 workspace `.env` 变量的命令，确认注入仍生效（验 spawnSpec 包装）；
  2. schedspawn：调 `list` 看任务清单、手动 fire 一次确认子agent派生链路；
  3. archive-retention / subagent-cleanup：各跑一次 `dryRun`，确认 sessions 目录布局读取正常；
  4. web UI：确认新增 `entry-customization` 内置条目装载、More 菜单出现 pin 交互（这是本区间最大的 UI 变化）；
  5. Models 页：确认 DeepSeek 卡片出现「跟随官方列表」行为。
- **行为适应提醒**：New Session 空白会话复用回归——依赖「New Session 每次全新会话」的旧习惯/流程需要适应；修改 preset 定义后注意「已加载的空白会话保留旧组合」的坑（官方 guide 的 Migration 一节）。
- **preset 漂移核对**：按本仓惯例升级后应核对内置 preset 与 `momojie-common` 用户副本漂移——本次调查范围未含 preset 副本（在 momojie-assistant 仓），**未执行**，留给升级执行时做。
- **rc.5 与 0.2.2-alpha 线的关系**：master 上 0.2.2-alpha.1/2（10-27，含 liveshare 等）尚未进入 rc.5；rc.5 内容 ≈ rc.4 + 少量文档/目录微调（§1 定位）。若近期要上 0.2.2，等下一个正式观察报告，不必用本报告替代。

## 5. 方法与局限

**有确凿来源的结论**：

- 包级内容变化清单：registry tarball（exact 版本号直下）逐文件 SHA256 对比，覆盖主包直接依赖 83 + web-app 依赖 133 + 插件依赖 21 个包；「纯版本号 bump」判定方法为把双方 package.json 中的版本串归一化后比较，其余文件哈希比对。
- 主包元包性质与依赖 diff：npm pack 两个版本解包对比。
- 用户可见行为变化：GitHub 上 docs/ 与 .agents/ 笔记的 tag 间 diff（compare API）+ raw.githubusercontent 按 tag 读原文（upgrade-guide、slots.md、providers.md、config-catalog 等）。
- commit 级叙事：compare `687f282e86...504a01a957` 的 15 个 commit + `commits?sha=master&since/until` 的 10-26→10-30 窗口列表。
- spawnSpec 存在性：rc.5 解包产物 grep。

**未确认 / 局限**：

1. **rc.5 的源码切点**：GitHub 无 tag、无 release commit、无可枚举的对应分支（CI 发版未推送形态，任务预案预期内）。因此「rc.5 相对 rc.4 的增量」只有 tarball 一侧证据（client-runner 目录文案、mcp-resources/agent-preset 文档、tool-cordis catalog、web-app 版本串）；rc.4→rc.5 之间 GitHub master 上的部分修复（如 10-27 的多选题预选修复 `bf8d8494ba`，其落包 client-ui-user-questions 在 rc.5 中与 rc.2 相同）**未进入 rc.5**——不能把 master 10-27 的全部提交当作 rc.5 内容。
2. **rc.2→rc.4 compare 的 15 个 commit 与「真实内容变化包」的映射不完全**：compare 的 DAG 口径与发版分支线存在 plumbing 差异（tag 间 compare 只给出 15 个 commit，而 master 同期可见更多 feature 提交，应属后续 sync 分支并入的时序差）；本报告以 tarball 内容为准，commit 号仅作辅助出处标注。
3. **UI 修复与包的一一对应**：dsh-client-ui-chat / settings-account / api-remotes 等包的 lib 变化未逐条定位到 commit（压缩产物，未做符号级归因），已在 §1 标注「commit 级对应未逐条确认」。
4. **@agentclientprotocol 等非 scoped 传递依赖**：未逐一对比（不在任何直接依赖清单中，且 ranged 解析两版一致的前提下不影响结论）。
5. **临时产物**：全部调查过程文件位于 `%TEMP%\dsh-verdiff\`，报告完成后删除；工作区内除本报告外无任何写入。

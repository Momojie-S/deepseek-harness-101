### 细节与注意点

- **本节最重要结论：6 个插件在 0.1.5-rc.3 下全部"无需改动"，且是字节级证明**——区间内插件接面涉及的 host 源码零变化，rc.1/rc.2 报告做过的全部 `文件:行号` 级验证对 rc.3 原样成立（本次抽样正向复核无一漂移）。
- **同 id 内置 entry 检查（AGENTS.md 记载的 0.1.5 workspace-files 教训项）**：rc.3 零源码变化 → 不存在新增内置 entry，无撞名风险。此项在跨大版本（0.1.6/0.1.7）时必须重做。
- **peer 版本范围（机械跟进项，非阻塞，延续上版结论）**：5 个带 peer 的插件仍钉 `@deepseek-ai/dsh-*@^0.1.1-rc.2` 系，按 node-semver 预发布规则匹配不到 `0.1.5-rc.3`；vendor 类 peer（cordis `^4.0.1` / timer `^1.1.3` / schemastery `^3.18.1`）与 pin 目标版本（4.0.2 / 1.1.4 / 3.18.2）匹配无碍；workspace-env 无 peer。本机 junction 解析与运行时不受影响，`dsh plugin add` 路径会有告警。
- **schedspawn 内部遗留文案不变**：prompt 两处引用 `subagent_model`（`src/index.ts:361/:374`），而 rc.3 官方全树 grep **无此工具名**（官方 subagent 工具注册名是 `subagent`，model selection 开启时另有共享工具 `list_subagent_models`，见 `packages/subagent/tool-subagent/README.md:83` 与 `packages/core/tools/tests/gen-tool-catalog.spec.ts:91`）——与版本无关的本仓文案问题，上版已提、原样还在。

## 5. 升级建议

- **可升可不升，运行时风险≈0**：代码字节不变、preset 不变、vendor 本机已是 pin 目标版本；对"已装好、不重装"的本机，rc.3 的收益（安装可复现性）几乎为零。
- **真正的决策点是"要不要直接跨 0.1.7-rc.1"**：主线已推进到 0.1.7-rc.1（npm 2026-09-23 13:44 UTC 发布；此前 0.1.6-alpha.1/2、0.1.7-alpha.1/2 已走完），rc.3 大概率是 0.1.5 线最后一个补丁。若近期计划跨大版本，**rc.3 可以跳过**（它没有产品内容），把调查与验证火力留给 0.1.7-rc.1——但那是另一次独立调查：变化量大、需重做全部接面核对 + 同 id 内置 entry 检查 + preset 漂移核对。
- **若决定升 rc.3**：`npm i -g @deepseek-ai/dsh@0.1.5-rc.3`（依赖集合与现装一致、vendor 版本不变，无新增安装面）→ 重启 web 服务 → 冒烟。
- **升级后优先验证**：无 rc.3 特有项，沿用上版清单即可——① pwsh 命令带 workspace `.env`（workspace-env 的 private 包装面）；② `.dsh/mcp.servers.yml` server 注册日志；③ subagent 派生 + `send_message` 一轮（schedspawn / idle-delivery 事件与 inbox 面）；④ 设置页 archive-retention 卡片读写；⑤ 浏览器过一眼 UI 正常出消息。
- **机械项（择期，同上版）**：5 个带 peer 的插件把 `@deepseek-ai/dsh-*` 范围 bump 到 `^0.1.5-rc.x`；顺手清理 schedspawn prompt 文案里的 `subagent_model` 引用。
